# IRIS メニューバー

勉強中に進捗を見るためだけにチャットを開かなくて済むように。

メニューバーの一行と、画面の上に出る帯と、進捗の四角と、質問を打つ一行。
すべて `IRIS HUD.app` という一つのアプリです。

## 作る

Swift のファイルは5つあり、まとめて1つの実行ファイルにします。

| ファイル | 中身 |
| --- | --- |
| `IrisMenuBar.swift` | 読み取り、文言、帯、進捗の四角、メニュー |
| `Hotkeys.swift` | `RegisterEventHotKey` による全体ショートカット |
| `Ask.swift` | 質問を打つ一行と、返ってきた答え |
| `Travel.swift` | 次の予定までの移動時間（CoreLocation と MapKit） |
| `main.swift` | 起動 |

```
swiftc -O -o iris-hud IrisMenuBar.swift Hotkeys.swift Ask.swift Travel.swift main.swift
```

Swift 以外に必要なものはありません。macOS に入っている `swiftc` だけで通ります。

## 入れる

手で置かないでください。`menubar/install.sh` が、作る・置く・署名する・開くまでをやります。

```
menubar/install.sh
```

置き場所は `~/Applications/IRIS HUD.app` です。実行ファイルは `Contents/MacOS/IRIS HUD`、
`Info.plist` はこのディレクトリのものがそのまま入ります。

手順がスクリプトになっているのは、手でやって二度失敗したからです。`IRIS HUD.new` に
直接ビルドして後から名前を変えると、署名は `IRIS HUD.new` という識別子を抱えたまま
`Info.plist` に結び付かず、**位置情報の確認ダイアログが一度も出なくなります**。
出ないので気付けません。だから作業用の名前でビルドし、動かしてから、最後に
バンドル全体を `com.user.iris.hud` として署名します。署名を最後にやることが
`Info.plist` を結び付けます。

`LSUIElement` を立ててあるので、Dock にも `⌘Tab` にも出ません。
ログイン時に開くには、システム設定 → 一般 → ログイン項目 へ `IRIS HUD.app` を足します。

## 署名

`menubar/signing-setup.sh` を一度だけ実行してください。

```
menubar/signing-setup.sh
```

ローカルの自己署名コード署名証明書（`IRIS Local Signing`）を作り、
`~/Library/Keychains/iris-signing.keychain-db` に入れます。

これが要る理由は一つです。ad-hoc 署名には証明書が無いので、アプリについて安定して
いるのは実行ファイルのハッシュだけになります。2026-08-22 に測ったところ、同一の
ソースからの2回のビルドは同じ CDHash を持ち、定数を一つ変えると別の CDHash に
なりました。TCC はそれを別のアプリとして扱うので、**ビルドし直すたびに位置情報の
許可を聞き直されます。** 作業中の午後には数分おきのダイアログです。

証明書があると、designated requirement が
`identifier "com.user.iris.hud" and certificate root = H"…"` になります。
これはコードが動いても動きません。許可を聞かれるのは最初の一度だけです。

ログインキーチェーンではありません。ログインパスワードを codesign に渡す理由が
無いからで、このキーチェーンにはこの証明書一つしか入っていません。パスワードが
スクリプトに平文で書いてあるのはそのためです。証明書はルートとして信頼させません
——codesign は要求しないことを確認済みで、自己署名ルートをシステム全体で信頼させる
のはこの機械のセキュリティに対する実質的な変更です。

証明書が無いときは `install.sh` は ad-hoc に落ちて、落ちたことを言います。失敗はしません。

## 帯

メニューバーの一行では、フルスクリーン中に見えません。macOS がメニューバーを
自動で隠すためで、**いちばん見たいときに消える**という、目的そのものを外す壊れ方
でした。帯はそれを直すために作ったものです。

高さ58ポイント、画面の幅いっぱい。左からコア、`IRIS` の文字、2行の文、
そして右端に3つの区画が縦罫で区切って並びます。

```
◎ IRIS  いまは待機中。                         薬理学  あと 12日 │ 今日の気温は26℃、曇り時々晴れです。 │ usage  CLAUDE 41%  CODEX 12%
        今日は 15:30 から「薬理学の復習」です。 明日は 09:00 からガウスです。
```

### 左（2行）

1行目が状態、2行目が予定です。1行目は「誰が誰を待っているか」の順に上書きします。

| 状態 | 1行目 |
| --- | --- |
| バックアップ失敗 | `バックアップに失敗しています。手元にしかないコミットが 3件あります。` |
| 承認待ち | `承認待ちが 2件あります。1件が進行中。` |
| 実行中 | `2件の作業が進行中。 費用は $0.07。` |
| 提案あり | `提案が 3件あります。` |
| 稼働中のセッション | `iris が 11分 作業中。 詰まっているものが 1件。` |
| 反応の無いセッション | `iris が 24分 反応していません。` |
| 何も動いていない | `待機中が 2件。` / `いまは待機中。` |
| 無応答 | `IRIS に接続できません。` |
| 台帳を読めない | `台帳を読めません。` |

稼働中は**分数と場所**を出します。「2件が稼働中」は、何かが起きていることだけを言って
待ち続けるかどうかを読み手に決めさせません。11分の `iris` は進行中の長い答えで、
11分の見覚えのないディレクトリは別の状況です。反応が無いセッションについて
「どれが、どこを見ればいいのか」の答えはディレクトリなので、ディレクトリを言います。

台帳の Blocked は、備考に未来の日付があるものと無いものを分けます。日付があるものは
「待ち」で、それは動かないので帯には出しません——6日間ずっと同じ文を出す行は、
読まれなくなります。日付の無いものだけが「詰まっている」です。

2行目は今日と明日、その順で両方出します。

```
今日は 15:30 から「薬理学の復習」です。 明日は 09:00 からガウスです。移動には 12分 かかります。
```

今日の残りが無ければ `今日の今後の予定はありません。` と言います。近い方だけを出して
いた頃は、午後が空いているのか読めていないだけなのかが区別できませんでした。

予定名は原則 `「」` で囲みますが、`/api/travel/next` の `knownPlaces` に載っている
場所名を含むときは囲みません。場所は語なので、`明日は 15:30 からガウスです。` の方が
文として読めます。移動時間は現在地から MapKit で計算します（後述）。

タスク番号は出しません。番号を覚えていない人にとって、番号は情報ではなく雑音です。

### 右（3区画）

| 区画 | 例 | 出所 |
| --- | --- | --- |
| 試験までの日数 | `薬理学  あと 12日` / `薬理学  今日` | `/api/exam/next` |
| 天気 | `今日の気温は26℃、曇り時々晴れです。` | `/api/weather` |
| usage | `usage  CLAUDE 41%  CODEX 12%` | `/api/usage/cli` |

試験は日付ではなく日数です。問いは「いつか」ではなく「あと何日か」で、日付を出すと
見るたびに引き算をさせることになります。残り1日以下で赤、4日以下で強調色。

天気の文はサーバが Shortcuts の「天気テキスト」（`IRIS_WEATHER_SHORTCUT` で変えられます）
を走らせて得たもので、帯は28文字で切って出すだけです。文言はユーザーが自分の
ショートカットに書いたものなので、ここでは書き換えません。取得できなければ
`天気を取得できません` と書きます。空欄にすると静かな午後に見えますが、実際の意味は
たいてい「依存しているショートカットの名前が変わったか消えた」で、何も欠けていないので
誰も見に行きません。

usage は Claude と Codex の週の使用率です。片方が取れなくても `—` を書いて残します
——数字が一つだけの行は、アシスタントが一つしかない機械に見えます。高い方が
90% を超えたら赤、70% で強調色。閾値を超えるまで隠す案は却下しました。問題になって
からしか見えない数字は、見張ることができません。

幅が足りないときに縮むのは真ん中の文です。右端から usage、試験、天気の順に強く
場所を保ちます——足りないときに欲しい順がその順だからです。

### 位置

`NSScreen.visibleFrame` の上端に置きます。この一つの式が両方を意味します。

- 通常時 — メニューバーと Dock を除いた領域なので、時計の下に収まる
- フルスクリーン時 — メニューバーが無いので、画面の一番上になる

幅だけは `frame` から取ります。`visibleFrame` は Dock も引くので、右に Dock があると
帯が画面の端まで届かず、後ろが覗く切り欠きができました。

### フルスクリーンの上に出るための3点

どれか一つでも欠けると、メニューバーと同じ壊れ方をします。

- `.canJoinAllSpaces` — デスクトップを跨いで付いてくる
- `.fullScreenAuxiliary` — **これが無いとフルスクリーンのアプリの上に出られません。**
  フルスクリーンは専用の Space を持つため、普通のウィンドウは越えられない
- ウィンドウレベルを `mainMenuWindow + 1` に — 降りてきたメニューバーに隠れない

### クリックと、どく動き

クリックは下へ抜けます。ただし左端168ポイントだけは別で、ここはボタンです
（押すと進捗の四角が開きます）。押されたことを見ているだけの監視では下のボタンにも
同時に届いてしまうので、ポインタがこの範囲にある間だけ `ignoresMouseEvents` を
外します。

そして帯自体が、手を伸ばすとどきます。クリックが抜けることは「邪魔でない」ことの
半分でしかなく、macOS は帯の存在を知らない（`visibleFrame` はメニューバーと Dock
しか勘定しない）ので、最大化したウィンドウはこの下に潜り、タブと閉じるボタンが
隠れます。ポインタが入ると帯は完全に透明になり、離れると戻ります。

メニューバーの項目か `⌥⌘B` で消せます。消した状態は次回起動にも残ります。

設計の経緯は `docs/hud-strip-design.md` にあります。

## ショートカット

`RegisterEventHotKey` を使うので、アクセシビリティ権限は要りません。キーボードを
監視するのではなく、この組み合わせだけを届けてもらう仕組みだからです。

| キー | 動き |
| --- | --- |
| `⌥⌘I` | IRIS を開く |
| `⌥⌘A` | 軽く押すと質問を打つ一行、0.28秒以上押し続けると押している間だけマイク |
| `⌥⌘B` | 帯の表示・非表示 |
| `⌥⌘D` | 進捗の四角の表示・非表示 |
| `⌥⌘K` | 今日一日の帯（もう一度押すと閉じる） |

`⌥⌘K` の帯は、**画面を開かずに絵を確かめられます。**実機の撮影は画面が消えて
いると取れず、開いている窓を探して切り出す手も Space やアプリの前後で外れます。

```
swiftc -O -o /tmp/render-day IrisMenuBar.swift Hotkeys.swift Ask.swift \
  Travel.swift Rail.swift Shape.swift Schedule.swift Day.swift tools/main.swift
/tmp/render-day out.png
```

描いているコード（`DayBandView`）をそのまま呼ぶので、見えているものと同じです
（窓の枠と見出しは含みません）。予定は `tools/main.swift` に直書き。

`⌥⌘A` が一つのキーで両方なのは、どちらも「IRIS に何か言う」という同じ意図だからです。
長押しの間はマイクが開き、キーを離すと閉じます。聞いている間は帯が
`聞いています。どうぞ。` に変わります——マイクが開いていることは、聞かなくても
見えなければならない唯一のものです。答えは帯に40秒間留まり、収まらない分は
`⌥⌘A` で開くパネルに全文があります。

他のアプリに取られている組み合わせは `NSLog` に出ます。登録の失敗は黙って起きて、
外からは「IRIS が変なことをした」ように見えるので。

## 位置情報

次の予定までの移動時間を出すためだけに使います。起動時に一度だけ聞きます——予定の
3時間前に、何も考えていないところへダイアログが出るのを避けるためです。

現在地は MapKit の `MKDirections.calculateETA` に渡されるだけで、IRIS はどこにも
保存せず、どこにも送りません。行き先は `/api/travel/next` がカレンダーと場所表から
決めます。答えは5分だけ持ちます——聞く理由は渋滞で、15分持った数字はもう道路の話を
していません。

Shortcuts の `移動時間を取得` は使いません。2026-08-22 にこの機械で測ったところ、
ジオコード済みの住所でも現在地から現在地でも、車でも徒歩でも、コマンドラインからも
エディタの実行ボタンからも、毎回空の結果を返しました。エラーも許可の確認も出ず、
同じ作りの天気のショートカットは毎回動きました。

## メニューバーの一行

一行に出せるのは十数文字なので、見るべき理由の強い順に上書きします。

| 表示 | 意味 |
| --- | --- |
| `IRIS ✕` | IRIS が応答しない |
| `IRIS ⚠` | 台帳を読めない |
| `IRIS !2` | 承認待ちが2件ある |
| `IRIS ⟳2` | エージェントが2件動いている |
| `IRIS ⚠3` | 台帳の状態を読めない項目が3件ある |
| `IRIS 12/15 ·1停` | 完了12/15、停止中が1件 |
| `IRIS 12/15` | 完了12/15 |

`✕` と `⚠` を数字と別扱いにしているのは、**0件と読めなかったが同じに見えてはいけない**からです。応答がないときに `0/0` と出すのが、この設計がいちばん避けたい壊れ方です。

メニューには「IRIS を開く」「IRIS に聞く」「帯を表示／隠す」「進捗を開く／閉じる」
「常時待ち受け」「コアを止める／動かす」「更新」「使用量を更新」「終了」が並びます。
同じ設定は進捗の四角の中にもあります——メニューバーのメニューはフルスクリーン中に
隠れるので、帯が直そうとしたのと同じ壊れ方を三度目にしないためです。

## 見ているもの

`http://127.0.0.1:3002` だけです。ループバックはサーバ側が無条件に信頼する経路なので、
トークンを持ちません。設定するものもありません。

```
/api/portfolio          台帳。これが取れなければ「接続できません」
/api/agent/runs         実行中のエージェントと費用
/api/approvals/pending  承認待ち
/api/proactive          提案
/api/calendar           今日と明日の予定
/api/budget             予算
/api/sessions?hours=8   稼働中・反応の無いコーディングセッション
/api/weather            天気
/api/exam/next          次の試験までの日数
/api/backup/repo        リポジトリのバックアップ状態
/api/usage/cli          Claude と Codex の週の使用率
/api/travel/next        次の行き先の住所と、既知の場所名
```

`/api/portfolio` だけが「そもそもスナップショットがあるか」を決めます。残りは補助で、
取れなければその行が消えるだけです。カレンダーが取れないことは、報告を止める理由に
なりません。

45秒ごとに読みます。台帳は手で編集され、エージェントは分単位で動くので、
これより速く読んでも同じ文字列を電池と引き換えに得るだけです。

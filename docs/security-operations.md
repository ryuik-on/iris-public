# IRISのローカル認証と開発の検査

IRISは127.0.0.1と::1だけで待ち受けます。同じMac上のAPI呼び出しにも認証が必要です。
HUDから開くと、一度だけ使える起動券でブラウザを認証します。HUDとMCPは所有者だけが
読める起動ごとの鍵を使います。両方の待ち受けを確保するまで鍵を公開しません。
専用Web Appはlocalhostで開きます。再起動すると前の鍵は無効になり、HUDが開き直します。

ターミナルから状態を取得する場合：

```sh
npm run --silent iris:request -- GET /api/briefing
npm run --silent iris:request -- GET /api/usage/cli
```

POSTなどの本文は標準入力で渡します。鍵をコマンド引数へ書かないでください。
端末外から使う場合はHTTPSのリバースプロキシを用意し、そのoriginを
`IRIS_PUBLIC_ORIGIN`へ設定します。トークンはSYSTEM画面で確認できます。
平文のLAN接続を有効にするために待ち受け先を広げないでください。
Viteの開発画面から接続するときは、その画面のoriginだけを
`IRIS_ALLOWED_ORIGINS`へ明示的に登録します。

自動開発はClaudeのrestrictedモードでファイルの読み書きだけを許します。
シェル・外部MCP・カスタムフックは渡しません。IRISの親プロセスが変更を記録し、
ネットワーク・個人ファイル・本物のGit管理情報・共有依存関係への書き込みを
拒否するmacOSの隔離環境で検査します。テストが参照するGit情報は候補のファイルから
作った使い捨てのものです。検査したコミットのSHAが変わった案は再検査します。
保護領域の変更には追加の確認が必要です。

同等の隔離を検証するまで、IRISからCodex/agyへの自動開発委任は開始しません。
手動でのCLI利用には影響しません。macOSの隔離が利用できない環境でも検査を
無制限に実行する代替動作はありません。

`npm run verify`は通常のテスト・ビルドと、実サーバーの認証・圧縮本文・OAuth表示、
macOSの隔離境界の検査を実行します。隔離境界の検査は、隔離環境の内側で再実行せず、
ホスト側から実施します。

# 使用量レール — 実装仕様書

作成 2026-08-31。**先に納品する引き継ぎ書**。途中で止まってもこれを読めば続けられる。

参考にした形: 画面右端の縦レールに、サービスごとのリング。押すと窓ごとの内訳（棒とリセットまでの日数）が出る。

## なぜ作るか

いまの帯は `usage  CLAUDE 34%  CODEX 11%` という一行で、**どちらの数字も「使った割合」なのに
そう読めない**。2026-08-28、別のセッションが `0%` を「残量ゼロ」と読み、**まったく手つかずの
Codex を避ける計画を立てた**。数字を字で出す限り、この誤読は繰り返される。

**リングは満ちていく。**空＝手つかず、満杯＝使い切り。字を読まなくても向きが分かる。

## 出せるデータ（2026-08-31 実測）

| | 使用 | リセット | 出所 |
|---|---|---|---|
| Codex 週 | 1% | 09-06 08:01 | rollout の `rate_limits.secondary`（窓 10080分） |
| Codex 5時間 | 1% | 08-31 07:03 | 同 `primary`（窓 300分） |
| Claude 週 | 取得可 | あり | `~/.claude/iris-usage.json` の `seven_day` |
| Claude 5時間 | 取得可 | あり | 同 `five_hour` |
| Gemini / agy | **読めない** | — | 契約に読み取り口が無い |

**Claude はステータス行が動いた後にしか埋まらない。**いまは60時間古い。
`POST /api/usage/refresh {"staleMinutes":0}` で取り直せる。

## 設計

### 1. リングは「使った割合」で満ちる

`0` が空、`100` が満杯。**残量ではない。**色は使用が増えるほど強くなる方向
（Palette.Band の `emphasis` → 警告色）。

### 2. 「0%」と「読めない」を別の見た目にする — **これが一番大事**

agy は**構造的に読めない**。0% のリングと同じ形で描けば「空いている」と誤解される。
2026-08-28 の事故がまさにそれだった。

- **読める 0%** … リングを描き、空のまま
- **読めない** … リングを描かず、灰色の点線と `—`

**この二つが見分けられないなら、レールを出す意味がない。**

### 3. 帯から usage を外す（同じ数字を二箇所に置かない）

いまの帯の `usage CLAUDE … CODEX …` は削る。**同じ数字が二箇所にあると必ず片方が古くなる** —
今日まで直し続けてきた形そのもの。帯には残りの情報（試験・天気・予定・委任）が残る。

### 4. 開いた瞬間に取りに行く

帯の高さ報告と同じ仕組み（`opening` の判定）を使い、**レールが現れたときだけ**
`refreshAllowance(home, 5)` を呼ぶ。閉じている間は何もしない。

### 5. 並べるのは3つ

`Claude` / `Codex` / `Gemini(agy)`。普段知りたいのは「どのベンダーが余っているか」で、
窓の内訳は展開したときで足りる。**Gemini は読めなくても常に出す** — 見えないと、
読めないこと自体を忘れる。

展開したカードに窓ごとの行:

```
Claude   週      12%   6d
         5時間    <1%   3h
Codex    週       1%   6d
         5時間     1%   5h
Gemini   —      読めません（契約に読み取り口がありません）
```

## 実装の足場

- `menubar/IrisMenuBar.swift`。既存の `final class Strip: NSPanel`（1329行）と
  `final class Dashboard: NSPanel`（1978行）が前例。**描画は一つのカスタム view の `draw` に集める** —
  Dashboard がそうしている（системのコントロールを並べると設定画面に見える）。
- 色は `Palette.Band`（`ground` `headline` `emphasis` `aside` `rule` `edge`）を使う。
  紫・マゼンタ・ラベンダーは使わない。
- 位置は画面右端。`NSScreen.frame` から取る（`visibleFrame` は Dock を引くので、
  Dock が右にあるこの機械では端まで届かない — 帯で踏んだ失敗）。
- サーバ側は既存の `GET /api/usage/cli` で足りる。**新しい endpoint は要らない。**

## 工数と振り分け

- レールの描画と展開: 量があり機械的 → **Codex か agy に委譲可**
- 「読めない」の描き分けと、帯からの usage 削除: **Claude が持つ**（誤読を作らないことが要件そのもの）
